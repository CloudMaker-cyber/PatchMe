# 任务 2 学习笔记：数据库与账号基础

> 对应任务卡：`docs/v3/03` 任务 2；对应清单：`docs/v3/05` "任务 2：Java、数据库与认证"。
> 验收结论：四项全部通过（密码 $2a$ 哈希入库、游客 401、伪造 userId 无效、空库 Flyway 全自动重建）。

## 一、05 清单逐条理解 + 代码落点

### 1. Controller / Service / Mapper / Entity / DTO/VO 的责任边界

- **Controller**：只做"翻译"——把 HTTP 请求翻成 Service 调用，把结果装进 `ApiResponse`。不写业务规则。
  例：`auth/AuthController.java` 登录成功后只负责把 token 写进 Set-Cookie 头，验证密码是 Service 的事。
- **Service**：业务规则 + 事务边界。
  例：`auth/AuthService.java` 判重邮箱/用户名、BCrypt 校验、账号状态检查，全在这层。
- **Mapper**：数据库读写接口（MyBatis-Plus `BaseMapper`），不含业务判断。
  例：`user/mapper/UserMapper.java` 只有一行 `extends BaseMapper<UserEntity>`。
- **Entity**：表结构的 Java 镜像，**永远不直接返回给前端**（含 password_hash、email、role 等敏感列）。
- **DTO/VO**：Request 方向叫 DTO（`auth/dto/RegisterRequest.java`），Response 方向叫 VO（`AuthController.LoginVO`、`MeController.MeVO`）。字段是白名单：VO 里没有的字段，前端永远拿不到。

一句话记忆：**敏感字段挡在 VO 这一层，权限判断挡在 Service 这一层，Controller 只是门卫。**

### 2. HTTP 状态码、全局异常处理、Bean Validation

- 状态码语义：400 参数不合法（40000）、401 未登录（40100）、403 无权限（40300）、409 冲突（40900，本轮为"邮箱已注册"新增）、500 兜底（50000）。
- `common/exception/GlobalExceptionHandler.java`：`BusinessException` → 用枚举自带状态码；校验失败 → 400；未知异常 → 500 且消息固定为"服务暂时不可用"，**不透传底层异常文本**（`GlobalExceptionHandlerTest.unexpectedExceptionNeverLeaksInternals` 专门验证 JDBC 连接串不外泄）。
- Bean Validation：约束写在 `RegisterRequest` 的 record 组件上（`@Email`、`@Size(min=8)`、`@Pattern("^[a-z0-9_]{4,20}$")`），Controller 参数加 `@Valid` 即触发，非法请求**进不了 Service**。

### 3. MySQL 主键、外键、联合唯一键、索引、事务

见 `backend/src/main/resources/db/migration/V2__core_tables.sql`：

- 主键：`users.id` 等自增（`IdType.AUTO`）；`user_profiles`/`user_settings` 用 `user_id` 做主键（1:1 从表，`IdType.INPUT`）。
- 外键：所有从表 `FOREIGN KEY ... REFERENCES users(id)`，数据库层兜底孤儿行（本轮清理测试账号时被 FK 拦过一次，正好证明它有效）。
- 联合唯一键：`post_tags(post_id,tag_id)`、`post_supports(post_id,user_id)`、`bookmarks(user_id,post_id)`——"同一用户给同一帖点一次支持"这种规则直接交给唯一键，不用代码查重。
- 索引：`idx_posts_created_status(created_at,status)` 服务首页默认流"未删除+可见按时间倒序"；`idx_replies_post_created(post_id,created_at)` 服务帖内回复列表。**联合索引字段顺序=查询条件顺序**（先过滤后排序的列在前）。
- 唯一约束：`users.email`、`user_profiles.username`。
- 事务：注册要同时写 users/user_profiles/user_settings 三张表，`AuthService.register` 标 `@Transactional`——任何一步失败三张表全回滚，不会出现"有账号没资料"的半截数据。

### 4. BCrypt 为什么不能解密、注册/登录流程

- BCrypt 是**单向哈希**不是加密：没有"解密"函数，只能 `matches(明文, 哈希)` 重新算一遍比对。每个哈希自带随机盐（所以同一密码每次注册入库的串都不同），长度固定 60、前缀 `$2a$`。
- 注册流程：校验 → 判重 → `passwordEncoder.encode(明文)` 存哈希 → 三表事务。
- 登录流程：按 email 查用户 → `matches` 比对 → 不区分"用户不存在/密码错"，统一回"邮箱或密码错误"（防账号枚举）→ 状态非 NORMAL 拒绝 → 签发 JWT。

### 5. JWT 结构、认证过滤器、SecurityContext、为什么不能信任前端 userId

- JWT = `header.payload.signature` 三段 Base64。payload 里只有 `sub`(userId) 和 `role`，**签名用服务端密钥（HS256）**，改一个字符验签就失败（`JwtServiceTest.tamperedTokenIsRejected`）。
- `auth/JwtAuthFilter.java` 每请求执行：从 HttpOnly Cookie（或 curl 用的 Bearer 头）取 token → `JwtService.parse` 验签 → 成功才往 `SecurityContext` 写入 `LoginUser`。
- `SecurityConfig` 规则：公开 GET 放行、`/api/admin/**` 要 ADMIN、其余必须登录；401/403 输出统一 JSON。
- **为什么不信任前端 userId**：任何请求参数、请求体里的 userId 都可能是伪造的。唯一可信来源是验过签的 JWT。结构性保证：`MeController.me(@AuthenticationPrincipal LoginUser)` 签名里根本没有 userId 参数可传——想伪造都没有入口（实测带 `?userId=999` 仍返回自己）。
- token 走 Cookie 不走 JSON 体：JS 读不到 HttpOnly Cookie，XSS 偷不走 token（`AuthControllerTest.loginPutsTokenOnlyInHttpOnlyCookie` 断言响应体无 token）。

### 6. Flyway 为什么比手工改数据库更可靠

- 手工改库的问题：改了什么没记录、换台机器/新同事从零搭建要口头传配方、生产库和代码版本对不上。
- Flyway：迁移脚本 `V1__baseline.sql`、`V2__core_tables.sql` 进 Git，**版本号即顺序**；启动时对照 `flyway_schema_history`，只跑没跑过的；已执行的脚本被改动会直接启动失败（checksum 校验）。库结构从此"随代码版本演进"。
- 本轮实测：`DROP DATABASE` + 空库启动 → V1+V2 自动执行 → 12 张表 + 种子数据一次到位（日志 `Successfully applied 2 migrations`）。

## 二、本模块开发者提问整理

1. **"git add frontend learning-notes 和 git add -A 有什么区别？"**
   指定路径只暂存这些目录的改动；`-A` 暂存全仓库所有变化（含误留的临时文件、甚至密钥文件）。我们的 `.env` 含真实密码/密钥且已在 `.gitignore`，用 `-A` 的风险是"以后某个未忽略的文件被顺手提交"。习惯：**永远按本轮改动的目录精确 add，提交前看 `git status`**。
2. **"为什么内置浏览器看还是有问题，别的浏览器正常？"**（验收期间）
   内置浏览器标签页在几十轮热更新后持有的旧懒加载 chunk 已失效，而外部浏览器是全新加载。代码没问题，是**缓存/陈旧会话**差异——这也是后来加 `router.onError` 自动重载和"修复后必须完整回归"规范的原因。
3. **"接下来干什么？"**——流程问题：每完成一个任务卡 → 我自检+验证 → 你验收 → git 提交 → 说"继续下一任务"。
4. **"怎么用 Workbench 看 password_hash 前缀 $2a$，说具体点"**
   操作路径：Workbench → `patchme-dev (docker)` 连接（版本警告点 Continue Anyway）→ Query 编辑器执行 `SELECT id, email, password_hash, role, status FROM users;`（`Ctrl+Shift+Enter`）。看三件事：哈希 60 位、前缀 `$2a$10$`（BCrypt 版本+强度 2¹⁰≈1024 轮）、明文不可见。当时库里被我清理成 0 行，所以先补注册了 salt_demo_a/b 两个**同密码**账号——两条哈希前 29 字符（盐）完全不同，直观证明"同一密码每次入库哈希都不同"，这就是彩虹表/撞库失效的原因。
5. **"帮我注册一个"**
   分工示范：起后端 → 调 `/api/auth/register` → 容器里查哈希 → 留给你在 Workbench 复核。你自己动手版：先用 API 工具（见下条）注册，再用 `SELECT LEFT(password_hash,29)` 对比盐。
6. **"有命令行以外的方式没有？命令行用不惯"**
   有，而且业界本来就用图形工具调 HTTP：**Apifox**（中文界面，Postman+Swagger+Mock 一体，国内后端岗简历可写）、Postman、或 VS Code 的 Thunder Client 插件。用法：新建 POST 请求 → URL 填 `http://localhost:8080/api/auth/register` → Body 选 JSON 粘贴 → 发送看响应。附带好处：图形工具按 UTF-8 发请求，不会踩 Git Bash 的 GBK 中文坑；Apifox 还能自动把登录响应的 Set-Cookie 带到后续请求，任务 3 验收带身份接口时直接复用。**任务 3 完成后前端会有真实注册/登录页，日常验收在浏览器里点就行，API 工具只用于排查后端问题。**

## 三、踩坑记录（本轮真实遇到）

| 坑 | 现象 | 根因与解法 |
|---|---|---|
| `@MapperScan` 写在启动类上 | 所有 `@WebMvcTest` 切片报 `sqlSessionFactory required` | 切片会处理启动类注解但没有数据源。挪进 `common/config/MyBatisConfig.java`（普通 @Configuration 不被切片加载） |
| `@MockitoBean(types=...)` 标字段 | `types attribute must be omitted when declared on a field` | 字段式直接 `@MockitoBean private UserMapper m;`，`types=` 只用于类级 |
| 切片扫描全部 Controller | 异常处理器测试因 AuthController 缺 Service 起不来 | `@WebMvcTest(controllers=TestController.class)` + `@Import(GlobalExceptionHandler.class)` 显式装配 |
| Git Bash 提交含中文 JSON | 注册返回 400 参数不合法 | 终端按 GBK 发出、服务端按 UTF-8 解不开。**是客户端编码不是服务端 bug**，用 `--data-binary @utf8文件` 解决 |
| 删除测试账号 | FK 报错 1451 | 有外键时必须**先删子表再删父表**（或 JOIN DELETE） |
| 停掉 mvn 后台任务 | 8080 仍被监听 | `spring-boot:run` 的 java 子进程会成孤儿，需按 PID 确认是自己的进程后 taskkill |

## 四、面试表述（30 秒版）

> 认证这块我用 Spring Security 无状态过滤器链：注册时密码只存 BCrypt 哈希，登录验密成功后签发 HS256 JWT，通过 HttpOnly SameSite=Lax Cookie 下发——JS 读不到，XSS 拿不走 token。每个请求由自定义过滤器验签，验过才写入 SecurityContext，业务代码通过 `@AuthenticationPrincipal` 拿当前用户，接口签名里根本不存在 userId 参数，所以"伪造 userId 越权"在结构上不可能。权限规则集中在 SecurityConfig：游客只能 GET 公开内容，管理端要求 ADMIN 角色，401/403 统一 JSON 不泄露堆栈。数据库用 Flyway 版本化迁移，删库后启动可从零重建全部表、索引和种子数据。这些都有测试：25 个用例覆盖签发验签、切片安全链路和异常收敛。
