## 一、05 清单逐条理解 + 代码落点

### 1. Docker 镜像：多阶段构建与非 root 运行

- `backend/Dockerfile`：第一阶段 `maven:3.9-eclipse-temurin-21` 编译打包，第二阶段 `eclipse-temurin:21-jre-alpine` 只带 JRE + 一个 jar——镜像从 ~500MB 级降到 ~200MB，且构建工具不进生产。
- 非 root：`addgroup -S patchme && adduser -S -D -H -u 100432 -G patchme patchme` 后 `USER patchme`。**两个坑**：busybox 的 `adduser -S -D` 不建组，必须先 `addgroup`（否则 `chown patchme:patchme` 报 invalid group）；命名卷首次挂载**继承镜像内目录属主**，所以要预先 `mkdir -p /app/logs && chown -R patchme:patchme /app`，不然 root 属主的卷让 logback 写文件失败、应用在日志初始化时崩溃循环。
- `COPY docker-settings.xml /root/.m2/settings.xml`：容器内 Maven 走 aliyun 公共镜像，直连 Central 在本机网络 50 分钟起步。
- `frontend/Dockerfile`：node 构建 `dist/` → nginx 镜像托管静态资源 + `/api` 反代后端（`nginx.conf`），同源部署。

### 2. 环境变量：`${VAR:?}` 快速失败

- `docker-compose.prod.yml` 对 DB 密码、ROOT 密码、`JWT_SECRET`、`APP_CORS_ORIGINS` 全部写 `${VAR:?错误文案}`：缺一个就在 `up` 前报错退出，**绝不会带着空密钥起服务**（已实测：删掉 JWT_SECRET 后 compose 直接拒绝启动）。
- `application-prod.yml` 里没有任何默认密钥兜底——`${JWT_SECRET}` 无 `:` 默认值，环境变量缺失时 Spring 启动失败。开发栈/生产栈的密钥从 `.env` 就物理隔离，生产 `.env` 在服务器上单独生成、`chmod 600`、永不进 Git。

### 3. CORS / HTTPS

- CORS 从 `APP_CORS_ORIGINS` 精确注入（`CorsConfig` 白名单），生产禁止 `*`、禁止残留 localhost:5173；同源部署（nginx 反代 `/api`）时跨域实际不发生，白名单是纵深防御。
- HTTPS 是上线闸门：`prod` profile 下 `APP_COOKIE_SECURE=true`，`pm_access` 带 `HttpOnly+Secure+SameSite=Lax`。**没有 TLS 不要邀请真实用户**（Secure Cookie 失效 = 凭据明文过网），部署文档第 2 节写明用 Caddy 自动签发或 certbot。

### 4. 数据库备份

- 落点在 `docs/deploy-production.md`：`docker compose exec -T mysql mysqldump --single-transaction --routines --triggers <db> | gzip > backup-$(date +%F).sql.gz`，cron 每日 + 保留 14 天 + **异机存放**；恢复演练命令也给了（备份不演练恢复等于没备份）。`--single-transaction` 靠 InnoDB 一致性快照，不锁表。
- 数据在命名卷 `patchme_prod_mysql_data` 里——`down -v` 会连卷删掉，文档明确警告内测期间禁用 `-v`。

### 5. 日志脱敏

- `logback-spring.xml` 注册自定义 `MaskingConverter`（`common/log/`），文件+控制台两条 appender 都过它。规则顺序很重要：**BEARER → Cookie(pm_access=…) → JWT 三段串 → 邮箱 → password 字段值**，先掐头再兜尾，替换为 `***`。
- 为什么在 Converter 层做：任何 `log.info("...")` 意外带上敏感串都会被统一拦截，不依赖每个开发者"记得别打日志"。单元测试 `MaskingConverterTest` + 实启动日志抽查（`Using generated security password=***`）双层证明。

### 6. 健康检查

- `GET /api/health`（`HealthController`）返回统一 `ApiResponse`；compose.prod 里 mysql/backend 各有 healthcheck，`backend` 对 mysql 是 `depends_on: condition: service_healthy`，`web` 同样等 backend healthy——`up -d` 之后整栈按依赖顺序就绪，不是"起了但没好"。
- 生产 backend healthcheck 用容器内 `wget /api/health | grep '"code":"0"'`：DB 连不上时 health 转红，配合 `restart: unless-stopped` 自愈。

### 7. 生产与本地配置隔离

- 三份配置各司其职：`application.yml`（dev：Swagger 开、cookie secure=false、本地 3307）、`application-prod.yml`（Swagger 关、cookie secure=true、无默认密钥）、`docker-compose.yml` vs `docker-compose.prod.yml`（独立项目名与独立卷，互不污染）。
- springdoc 的 prod 关闭有个验证细节：`springdoc.*.enabled=false` 让**后端内部** `/v3/api-docs` 404，但经 nginx 访问会命中 SPA history 兜底返回 200 index.html——不是泄露。文档里把验证方法写成 `docker compose exec backend wget -S http://127.0.0.1:8080/v3/api-docs`（容器内直连才算数）。

### 8. 集成测试（任务卡"补齐集成测试"）

- `integration/DualAccountJourneyIntegrationTest`：Testcontainers 起一次性真实 MySQL 8.4，走完整 HTTP 栈（Security 过滤链 + JWT Cookie + Flyway 迁移），双账号+管理员跑完 04 上线清单核心矩阵：匿名零泄露、公开主页、单向闸、越权拒绝、举报不自动处罚、确认下架、状态写闸、软删除、通知仅本人、发帖限流。
- 与单测的分工：单测 mock Mapper 测业务规则，IT 用真库真 HTTP 测"拼起来对不对"——正是任务 3"单测全绿但 SQL 一启就炸"教训的工程化答案。`@Testcontainers(disabledWithoutDocker = true)`：无 Docker 环境自动跳过不假红，但本机验收要求零跳过。

## 三、踩坑记录（本轮真实遇到）

| 坑 | 现象 | 根因与解法 |
|---|---|---|
| Testcontainers `@Container` 实例字段 | IT 连不上库/容器没起 | 必须 **static** 字段 + `@Testcontainers(disabledWithoutDocker=true)`；另配 `@DynamicPropertySource` 覆盖数据源并把 `spring.autoconfigure.exclude` 清空，否则 prod yml 的占位符先炸 |
| 原生 `window.confirm` 卡死自动化 | 点"执行处置"后页面级 CDP 全部超时 | 浏览器原生对话框阻塞页面线程。**最吓人的是**：dialog 在约 2 分钟后被自动接受，把我以为"没点成"的 RESTRICT 真的执行了（发生在 API UNBAN 之后）。教训：**timeout ≠ 没执行，动作后必须回查服务器状态**；自动化前先 `evaluate_script` 覆写 `window.confirm=()=>true` |
| 非 root 容器启动崩溃循环 | `FileNotFoundException: /app/logs/patchme-backend.log (Permission denied)` | logback 文件 appender 初始化即抛 → 应用退出。根因链：命名卷首次挂载继承镜像目录属主（root）。修复：镜像里预建 `/app/logs` 并 chown 给 app 用户；且**已存在的旧卷要 `docker volume rm` 重建**（卷属主只在首次使用时初始化）。第一次修复还失败：busybox `adduser -D` 不建组 → `addgroup` 先行 |
| 容器内 Maven 直连 Central | 构建 50+ 分钟无进展 | 本机网络到 registry 不稳。`docker-settings.xml`（aliyun public）COPY 进构建镜像，构建缩到几分钟 |
| Swagger 关闭"验证不通过" | 经 nginx 请求 `/v3/api-docs` 返回 200，以为没关干净 | 是 SPA history 兜底返回了 index.html，后端内部实为 404。验证必须在容器内直连 8080；文档同步改写，免得用户照旧命令误判 |
| verify6b 三个假 FAIL | 断言明明对却报红 | ① REPORT 通知文案是"不予处理"不是枚举名；② feed 的 `data` 是 PostSummaryVO 列表不是 `{items:[{post}]}`；③ 公开帖 author 带 nickname 是设计而非泄露——改为"匿名帖 author 键集必须恰好是 {mode}"。断 JSON 用 JSON 解析逐字段判，别文本 grep |
| vite 探活 curl 000 | 以为用户 dev 服务器挂了 | vite 只绑 IPv6 localhost，`curl 127.0.0.1:5173` 必失败；用 `http://localhost:5173/` |

## 四、面试表述（30 秒版）

> 部署这块我按"单机 Docker Compose 内测"设计：后端多阶段镜像跑在 JRE Alpine 非 root 用户上，前端 nginx 托管静态资源并反代 API，实现同源部署；所有密钥经 `${VAR:?}` 强制从服务器上的 .env 注入，缺一个就拒绝启动，生产 profile 里没有默认值兜底，Jwt secret 开发与生产物理隔离。日志在 logback Converter 层做脱敏，token、JWT、邮箱、密码字段统一打星，不靠开发者自觉。健康检查按依赖编排，MySQL→后端→前端逐级 healthy 才算起。最有价值的是把测试补到了集成层：Testcontainers 起真实 MySQL，双账号走完整 HTTP 栈跑匿名零泄露、越权、状态写闸、限流、软删的全链路矩阵。生产与本地三份配置完全隔离，Swagger 只在 dev 开。上线手册还包括 mysqldump 每日备份加恢复演练，HTTPS 作为邀请真实用户的前置闸门。
