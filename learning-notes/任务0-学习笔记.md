# 任务 0 学习笔记 — 工程基线

> 本文件是学习档案：对照 `docs/v3/05-学习与面试清单.md` 的"任务 0"要求逐条解释概念在本工程的落点，并整理本轮开发中问过的问题。

## 一、05 清单要求理解的概念 → 在本工程的具体体现

### 1. Maven 依赖

**是什么**：Maven 用 `pom.xml` 描述"我的项目需要什么版本的什么库"，并自动从仓库（你配置的阿里云镜像）下载到本地 `~/.m2/repository`。

**体现在哪**：`backend/pom.xml`
- `<parent>spring-boot-starter-parent</parent>`：继承 Spring Boot 的"版本字典"（BOM）。子依赖如 `flyway-core`、`mysql-connector-j` 都不写版本号，由 parent 统一锁定——这就是为什么升级 Boot 版本一处生效、不会版本打架。
- `<properties><java.version>21</java.version>`：编译目标 JDK。
- 唯一手写的版本是 `mybatis-plus.version`，因为 MyBatis-Plus 不属于 Boot 官方 BOM 管理。

### 2. Spring Boot 启动类与配置文件

**启动类**：`backend/src/main/java/com/patchme/PatchMeApplication.java`。
`@SpringBootApplication` 是三个注解的组合：标记这是配置类 + 开启自动配置（扫描 classpath 决定装配哪些 Bean，例如发现有 MyBatis-Plus 就自动配 SqlSessionFactory）+ 开启组件扫描（默认扫本包及子包，所以 `com.patchme.**` 下的 `@RestController`、`@Service` 都能被找到）。

**配置文件**：
- `backend/src/main/resources/application.yml`：主配置。注意 `${DB_PASSWORD}` 这类占位符——**配置文件里永远没有真实密码**，值从环境变量注入（开发机来自 `.env`，生产来自部署平台）。
- `backend/src/test/resources/application.yml`：测试专用，同名文件在 test 目录优先加载，它排除了数据源自动配置，所以 `mvn test` 不需要本机 MySQL。这是"测试不依赖外部环境"的关键设计。

### 3. Vue 单文件组件、ref/reactive、props/emits

**单文件组件（SFC）**：一个 `.vue` 文件 = 模板（HTML）+ 逻辑（`<script setup lang="ts">`）+ 样式（`<style scoped>`，scoped 表示样式只作用于本组件）。例：`frontend/src/views/HomeView.vue`。

**ref**：`HomeView.vue` 里 `const health = ref<HealthState>('checking')`——`ref` 创建一个响应式容器，脚本里读写要用 `.value`，模板里自动解包。数据一变，用到它的 DOM 自动更新。`reactive` 是对象版（直接代理对象），本项目约定优先用 `ref`，类型推断更友好。

**props/emits**：任务 0 还没写自定义子组件（页面里只有路由出口），任务 1 拆组件时会大量出现：父传子用 props（单向只读），子通知父用 emits。

### 4. Vue Router 与 Pinia 的用途

- **Router**（`frontend/src/router/index.ts`）：单页应用不刷新页面也能换视图，靠路由表把 URL 映射到组件。`/post`、`/me` 用了 `() => import(...)` 懒加载——首次访问才下载该页面代码包（所以 build 输出里能看到 MeView/PostView 各自独立的 js 文件）。
- **Pinia**（`main.ts` 中 `app.use(createPinia())`）：跨组件共享的全局状态仓库。任务 0 只注册未使用；任务 1 起放筛选条件、会话状态。**注意规范约束：Pinia 只存 UI/会话状态，绝不存敏感资料。**

### 5. 前后端分别如何启动

见根 `README.md`"本地启动"。一句话版：MySQL 容器（docker compose）→ 后端 8080（mvn spring-boot:run）→ 前端 5173（npm run dev，`/api` 请求由 Vite 代理转发到 8080，浏览器视角同源所以无跨域问题）。

### 6. 统一响应与全局异常（本模块的"框架级"收获）

- 所有接口返回 `ApiResponse{code,message,data}`（`common/api/ApiResponse.java`）；
- `GlobalExceptionHandler` 把业务异常、参数校验失败、未知异常全部收敛成同一 JSON 形状，未知异常固定返回"服务暂时不可用"，**堆栈只进日志不进响应**——测试 `unexpectedExceptionNeverLeaksInternals` 专门验证了这一点（异常消息里埋了"jdbc:mysql://secret-host"，断言它不会出现在 JSON 里）。

## 二、面试可讲（任务 0 部分）

**为什么前后端分离？** 各端独立演进与部署（前端静态资源走 CDN/Nginx，后端只管 API）；技术栈解耦；同一 API 未来可复用于小程序/App；权限边界清晰——前端只是消费者。

**为什么单体而不是微服务？** 当前规模（校园社区、首版功能少）微服务的分布式事务、部署复杂度、服务治理全是纯成本。单体内部用包结构（auth/post/reply/...）划清边界，未来真出现独立扩容需求再拆不迟。**面试加分说法：我保留的是"模块化单体"，边界在代码层已经存在。**

**为什么用户端不用 Element Plus？** 产品定位是"手账感"的倾诉社区，组件库会带来强烈的后台管理系统视觉模板感；且用户端组件少而定制深，自写 CSS 更可控、包体更小。Element Plus 只留给管理后台（任务 5）。

## 三、本轮开发中问过的问题（整理归档）

| 问题 | 精简答案 |
|---|---|
| 怎么验收？ | A 档=测试/构建/密钥自检（不依赖环境）；B 档=真实链路：容器起库 → Flyway 迁移 → 健康检查 → 前端联通 → SQL 复核 |
| Maven settings.xml 坏在哪？ | 第 167 行有孤立 `-->`（无 `<!--` 配对），XML 解析器在标签位置遇到裸文本即 FATAL；修复=删掉它并只保留一个 `mirrorOf=central` 的阿里云镜像；验证=`mvn help:effective-settings` + 不带临时参数跑 `mvn test` |
| `cached from a remote repository ID that is unavailable` 是什么？ | 正常现象：本地缓存的构件来自 central，现在镜像 ID 变了，Maven 一次性重新确认可下载，之后不再出现 |
| Docker 装完 hello-world 失败？ | `registry-1.docker.io` 国内不可直连 → Docker Engine 配 `registry-mirrors`；`short read: unexpected EOF` 是镜像源偶发截断，重试即恢复 |
| 这些命令在哪运行？各步骤干嘛？ | 全在 Git Bash；长驻进程（后端/前端 dev server）各占一个窗口。4 管密钥、5 起库、6 验证后端+迁移、7 验证前端+接口、8 用 SQL 眼见为实 |
| 为什么端口是 3307？ | 本机已有原生 mysqld 占 3306（未动它）；compose 与后端共用 `.env` 的 `DB_PORT`，改一处两边生效——这就是"单一配置源"的好处 |
| flyway_schema_history 是干什么的？ | Flyway 的记账本：记录已应用迁移的版本、校验和、时间、结果；启动时对比脚本目录增量执行，checksum 防手工漂移，保证任何空库都能重放出一致结构 |
| Workbench 连不上/警告？ | Workbench 不自动发现 Docker 容器，需手动新建连接指向 127.0.0.1:3307；8.0 CE 对 8.4 服务器弹兼容性警告，Continue Anyway 即可，基础查表不受影响 |
