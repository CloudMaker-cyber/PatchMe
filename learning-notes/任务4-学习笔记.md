## 一、05 清单逐条理解 + 代码落点

### 1. 软删除与硬删除的区别

- 硬删除 = `DELETE` 掉整行；软删除 = 行留在库里，只写一个 `deleted_at` 时间戳。
- 落点：`post/PostService.deletePost`（PostService.java:155）只做 `post.setDeletedAt(LocalDateTime.now())` + `updateById`，回复删除同理（`ReplyService`）。
- 为什么选软删：**行还在，外键引用（回复、通知 payload 里的 id）不会悬空**；风控/审计需要"删过什么"可追溯；且匿名承诺的关键是"删了就再也拿不回来"，靠的是读路径统一封死，而不是把写路径的数据抹光。

### 2. 为什么查询必须统一加 `deleted_at IS NULL`

- 软删除的命门是"漏掉一处过滤 = 已删内容复活"。所以过滤不能散落在每个调用点"记得写"，而是两个集中点：
  - **单条读**：`requireVisiblePost(postId)`（PostService.java:173）——`deleted_at != null` 或状态非 NORMAL 一律抛 `NOT_FOUND "内容不存在或已删除"`；详情、回复、举报、互动全部先过这道闸。
  - **列表读**：`PostMapper` 的自定义 SQL 投影里固定 `WHERE p.deleted_at IS NULL`。
- 对外表现三处一致：详情页 404、首页流消失、分享链接打开也是 404——**同一个闸，三种入口都撞在同一堵墙上**，这就是"删除后避免分享链接泄露"的答案。
- 越权语义也收敛：非楼主删除返回 403"只有楼主可以执行该操作"，重复删除已删内容返回 404（幂等，不泄露"曾经存在"之外的信息）。

### 3. 通知如何由回复事件产生

- 生成点在 `ReplyService.create` 成功后：`notificationService.onReply(post.getAuthorId(), userId, postId, reply.getId(), reply.getBody())`（ReplyService.java:77），**与插入回复同一事务**——回复落库则通知必在，回滚则都不在。
- 三条降噪/守密规则（`interaction/NotificationService`）：
  - 楼主回复自己的帖子不生成（`recipientUserId.equals(replierUserId)` 直接 return）；
  - 接收者 `reply_notification_enabled=false` 则不生成（读 `user_settings`）；
  - **payload 只含 `postId/replyId/excerpt`（正文截断 80 字），绝不含回复者身份**——匿名回复只说"有人回复了你"，通知本身不能变成反查匿名者的通道。

### 4. 浏览历史为什么只按当前用户查询

- 数据模型：`browsing_history` 联合主键 `(user_id, post_id)`（V3 迁移），重复浏览同一帖走 UPSERT `touch` 只刷新时间——天然去重。
- 所有读/写路径的 `userId` 只来自 `@AuthenticationPrincipal`（JWT），**接口里根本不存在"查别人历史"的参数**，越权无从伪造。
- 用户可控三件套：`history_enabled=false` 后不再记录（旧记录保留）；"一键清空"按 `user_id` 全删；只保留最近 30 天——清理逻辑挂在写入时顺手做（`recordView` 先 `DELETE viewed_at < cutoff`），不需要调度器。

### 5. 为什么 `robots.txt` 不能替代访问权限

- 本项目双保险：`frontend/public/robots.txt` 全站 Disallow + `index.html` 的 `<meta name="robots" content="noindex, nofollow">`。
- 但这只是"君子协定"：恶意爬虫完全无视 robots.txt。**真正的防线在服务端**——删除的帖子 API 返回 404（对爬虫和人一样）、"我的"内容/通知/历史只按 token 身份查询、公开主页强制 `identity_mode='PUBLIC'`。robots/noindex 解决的是"正常搜索引擎别收录匿名社区"，鉴权解决的是"任何人拿不到不该拿的"，两者不可互替。

## 四、面试表述（30 秒版）

> 删除我做的是软删除：只写 `deleted_at`，行保留，为的是引用完整和审计可追溯；但读路径统一收口成一个可见性闸——未删除且状态正常才可见，否则 404。所以详情页、首页流、别人手里的分享链接撞的是同一堵墙，不存在"删了但某个入口还能翻出来"。通知由回复事件在同一事务里生成，payload 只有帖子 id、回复 id 和 80 字摘要，绝不携带回复者身份，匿名回复不会变成反查通道；楼主自回和关闭开关都不产生通知。浏览历史以 `(user_id, post_id)` 联合主键 UPSERT 去重，读写只用 JWT 身份，接口上不存在查别人历史的路径，支持 30 天保留、一键关闭、一键清空。robots.txt 和 noindex 只是防搜索引擎的辅助，真正的访问控制在服务端。这些有 88 个单测加 46 项真实库端到端断言兜底。
