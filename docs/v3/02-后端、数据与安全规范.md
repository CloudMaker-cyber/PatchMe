# 02｜后端、数据与安全规范

## 后端分层

```text
Controller      接收 HTTP 参数、Bean Validation、统一响应
Service         业务规则、权限/归属校验、事务
Mapper          MyBatis-Plus 查询与必要自定义 SQL
Entity          数据表映射，只在后端内部使用
DTO / VO        请求 DTO 与响应 VO，严格控制返回字段
Security        JWT 解析、认证、授权、当前用户上下文
```

Controller 不直接操作 Mapper；前端不能直接访问数据库。跨表写操作、删除、标记有帮助、限制账号等用 `@Transactional` 保证原子性。

## 认证与权限

开发/内测：邮箱+密码注册登录。正式上线前再增加邮箱验证/找回密码；不要让邮件额度阻塞本地测试。

- `users` 表保存 BCrypt 密码哈希，绝不保存明文。
- 登录成功签发短期 access token 与更安全的刷新方案（首版可先实现短期 JWT + 重新登录，明确记录限制；正式公开前补 refresh token 或 HttpOnly Cookie 方案）。
- 推荐 JWT 放 HttpOnly、Secure、SameSite Cookie，降低前端脚本窃取风险；前端不得自行伪造“已登录”。
- `SecurityFilterChain` 区分公开 GET 接口、需要登录接口和 `/api/admin/**` 管理员接口。
- `CurrentUser` 从 JWT 的 userId 提取。任何 `userId` 请求参数都不能作为权限依据。

## 匿名安全的实现方式

禁止将 Entity 直接返回 JSON。必须使用两种公开响应 VO：

- `PublicPostVO`：id、意图、标题/正文、标签、时间、回复数、支持数、评论状态、作者展示对象；不含 authorId、schoolId、majorId、邮箱、内部状态。
- `PublicReplyVO`：id、帖子 id、正文、时间、有帮助标记、作者展示对象；不含 authorId。

作者展示对象根据 `identityMode` 由后端构造：

- 匿名：只返回 `{ mode: "anonymous" }`。
- 公开：返回 `{ mode: "public", username, nickname, avatarUrl }`。

学校/专业筛选在 Mapper SQL 的 `WHERE` 条件中完成，但不映射到 `PublicPostVO`。公开主页查询必须加 `identity_mode='PUBLIC'` 且按公开用户名过滤。我的内容查询必须按 `author_id = currentUserId`，返回自己的内容时才可识别内容归属。

## 接口轮廓

```text
POST /api/auth/register          POST /api/auth/login          POST /api/auth/logout
GET  /api/posts                  POST /api/posts              GET /api/posts/{id}
POST /api/posts/{id}/replies     POST /api/posts/{id}/support POST /api/posts/{id}/bookmark
PATCH /api/posts/{id}/comments   PATCH /api/replies/{id}/helpful
DELETE /api/posts/{id}           DELETE /api/replies/{id}
GET  /api/users/{username}       GET /api/me/posts            GET /api/me/replies
GET  /api/me/bookmarks           GET /api/me/history          DELETE /api/me/history
GET  /api/notifications          PATCH /api/notifications/read
POST /api/reports                POST /api/blocks
GET/POST/PATCH /api/admin/...    # 管理员专用
```

接口以统一 JSON 响应和全局异常处理返回，不能把 SQL 异常、堆栈、密码或内部 ID 暴露给浏览器。

## 任务 5 风控原则

- 在 Service 层实现发帖、回复、举报、登录失败的限流；初版可用 MySQL 计数窗口，后续压力出现后迁移 Redis。
- 检测联系方式、外链、广告/诈骗词；服务端二次验证，前端提示只是体验辅助。
- 处罚以人工核实的违规记录为依据：normal → warned → observed → restricted → banned。
- 管理员每次操作写审计日志，并向用户生成处理通知；永不泄露举报人。
