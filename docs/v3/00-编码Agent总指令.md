# 人生补丁包 V3：主编码 Agent 总指令

`docs/v3/` 是本项目 Java 全栈版本的唯一有效规范。不得修改或依赖 `docs/v2/`，也不得修补当前旧工程；V3 必须在新的干净工程目录中从零实现。

## 固定架构

```text
Vue 3 + TypeScript + Vite（用户端与管理端前端）
             ↓ REST / JSON
Spring Boot 单体后端（Java 21）
             ↓ MyBatis-Plus + Flyway
MySQL 8
```

- 用户端用 Vue 3 自定义 CSS/SCSS；Element Plus 仅用于管理后台与少量通用表单控件，不能把用户端做成后台模板。
- 后端采用 Spring Boot 3.5.x、Spring Security、JWT、MyBatis-Plus、Bean Validation、Flyway；版本在初始化时选择彼此兼容的当前稳定小版本并锁定。
- 采用前后端分离的单体架构。不要引入微服务、消息队列、Redis、搜索引擎或 AI 服务，除非后续任务明确要求。

## 必读与任务边界

开始前必须阅读：

1. `01-产品与交互规范.md`
2. `02-后端、数据与安全规范.md`
3. `03-开发循环与任务卡.md`
4. `05-学习与面试清单.md`

每轮只执行一张任务卡，完成后停止。发现需求冲突、安全漏洞或需要开发者在外部平台操作时，要先报告，不能自行扩大范围。

## 不可违反的安全规则

- 真实用户 ID、密码哈希、邮箱、JWT 密钥、数据库密码、管理员状态、举报内容和审核记录绝不返回给普通前端。
- 匿名内容的 API 响应不能含昵称、头像、主页链接、学校、专业方向、稳定身份标识或可反推账号的字段。
- 不能只依靠前端隐藏匿名资料；必须由后端 Service、查询 SQL 和 Response DTO 共同保证。
- 所有需要登录的接口从 Spring Security `Authentication` 获取当前用户，不信任前端传来的 `userId`、作者 ID、角色或内容状态。
- 每个资源修改、删除、楼主操作均在 Service 层进行归属校验；控制器只负责参数接收和返回。
- 密码仅由 Spring Security 的 `PasswordEncoder` 哈希后存入数据库，不能记录、回显或写进日志。
- 所有密钥仅在本机/部署平台环境变量中配置；不得读取、输出、提交或在聊天中要求 `.env`、数据库密码、JWT 密钥、云平台 Token。

## 可扩展性与健壮性（硬性要求）

本项目后续会持续新增功能，每一轮实现都必须以"下一轮不用推翻重来"为标准：

- 严守分层职责：Controller 只做翻译，Service 收敛业务与权限规则，Mapper 只做数据访问，跨层调用与旁路（Controller 直连 Mapper、前端拼业务规则）一律禁止。职责清晰的边界就是将来最小的改动面。
- 把"可预见的变化"挪到唯一点位：类型/状态/身份用枚举与状态机而不是散落的魔法字符串；投影 SQL、常量、限制阈值（如分页上限）单点定义；展示文案由枚举映射单点维护。
- 接口即契约：REST 路径、请求 DTO、响应 VO 是对前端的承诺。新增一律用可选字段/新端点；修改或删除既有字段语义属于破坏性变更，必须先报告并评估影响，不得静默改。
- 所有业务失败经 `BusinessException` + `ErrorCode` 走全局异常处理，统一 ApiResponse 信封；禁止吞异常、禁止把底层异常文本透传给前端。
- 数据库结构变更只允许通过新增 Flyway 增量迁移：新列保持可空或带默认值，保证旧行与旧代码仍可用；禁止改写已执行的历史迁移。
- 每条新安全规则与新行为必须配回归测试；禁止为让实现通过而修改或删除既有测试——既有测试是行为基线。
- 可扩展 ≠ 提前实现用不上的功能：只留结构性接缝（枚举、白名单投影、单点常量、分层边界），明确禁止为"假想的未来需求"制造投机抽象、多余接口与配置开关。

## 强制开发循环

1. **理解**：读任务卡与相关现有代码，说明要改什么、为什么、有哪些风险。
2. **实现**：严格限定在本任务，按 Controller → Service → Mapper → Entity/DTO 分层。
3. **验证**：运行后端测试与构建、前端 lint/构建；为权限和数据库规则提供可复制测试步骤。
4. **自检**：验证匿名隔离、越权、输入校验、异常响应、删除后可见性。
5. **交付**：列出文件改动、命令结果、手工验收、开发者外部操作、未完成范围，然后停止。

## 每轮交付格式

```text
完成：任务 N — 名称
改动：文件及用途
验证：实际执行命令和结果；手工测试步骤
开发者操作：需要在 MySQL / GitHub / 部署平台执行的操作；无则写“无”
学习提示：本任务中开发者应阅读的核心类/概念
未完成：仅列当前任务以外的项目
```

## 学习整合（硬性要求，生成时机见下）

学习笔记文件 `learning-notes/任务N-学习笔记.md` **不在开发交付当轮定稿**。
生成/定稿时机：开发者明确说**"开发确认完成"**之后。原因：交付后开发者通常还会继续
提问（验收操作指导、工具用法等），这些提问同样必须进笔记，提前定稿会漏记并返工。

开发交付当轮：交付报告照出（含"学习提示"节），笔记可以不建；若提前起草，须注明"未定稿"。
"开发确认完成"当轮：把该模块**从开工到确认完成期间开发者的全部提问与答复**一并整理定稿，
该笔记更新与验收产物一起纳入同一次 git 提交。

定稿内容至少包括：

1. 逐条解释 `05-学习与面试清单.md` 中该任务要求理解的概念：用通俗中文说明它是什么、
   **具体体现在本工程的哪些文件/类/配置中**（给出路径），以及面试时如何表述；
2. 从本模块开工到"开发确认完成"期间，开发者问过的所有问题，及其答案的精简整理
   （含踩坑与排错过程，如环境、端口、镜像源、工具使用、验收操作指导等）；
3. 本模块的动手小练习与需要重点阅读的 3–5 个文件清单。

该文件随代码一起提交 Git，作为开发者求职准备的学习档案。
