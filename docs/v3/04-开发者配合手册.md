# 04｜开发者配合手册

你不需要亲自写每一行代码，但你必须掌控账号、密钥、数据库、部署和验收。AI 负责实现，不拥有生产环境权限。

## 一次性准备

### GitHub

- 创建自己名下的私有仓库；每张任务卡验收后提交一次。
- 确保 `.env`、`application-local.yml`、数据库备份、日志、用户数据在 `.gitignore`。
- 公开开源前运行密钥扫描并检查整个 Git 历史；泄露过的密钥必须在平台中轮换，而不是只删除文件。

### 本地工具

- JDK 21、Maven、Node.js LTS、MySQL 8（或 Docker Desktop）、Git、VS Code / IntelliJ IDEA。
- 用 Docker Compose 启动本地 MySQL；后端运行 Flyway 自动建表；不要手工改表替代迁移。

### 本地环境变量

由你在后端的本地环境文件填写，示例：

```env
DB_HOST=localhost
DB_PORT=3306
DB_NAME=patchme
DB_USERNAME=patchme_app
DB_PASSWORD=自行生成的本地密码
JWT_SECRET=至少32字节的随机字符串
APP_CORS_ORIGINS=http://localhost:5173
```

不要将真实值发给 AI。生产环境使用不同的强密码和 JWT 密钥。

## 每次 Agent 交付后的动作

1. 运行它报告的后端测试和构建、前端 lint 和构建。
2. 用两个测试账号 A/B 按任务卡手工验证，不只看页面截图。
3. 遇数据库迁移：先审阅 `Vn__*.sql`，在本地空库运行；通过后才用于测试/生产库。
4. 通过验收后提交 Git；失败时保留命令输出、浏览器网络错误、后端日志（先遮住密钥）再找审查 Agent。

## 双账号匿名验收

| 场景 | 必须结果 |
|---|---|
| A 匿名发帖，B 查看 | 无昵称、头像、主页、学校、专业、内部 ID |
| A 公开发帖，B 查看 | 可进入公开主页，只见 A 的公开内容 |
| B 试图改/删 A 内容 | API 返回拒绝，数据库不变化 |
| A 查看“我的” | 可看自己匿名/公开内容；B 无法访问 |
| A 删除匿名帖 | 首页、详情、分享链接均无原文 |
| B 举报内容 | A 不知道举报人；处罚不因一次举报自动触发 |

## 部署时你需要做的事

- 选择并创建你自己控制的云服务器/托管数据库；首版可一台 Linux 服务器使用 Docker Compose 运行后端、前端静态站点代理与 MySQL，但生产数据库最好使用托管服务或至少自动备份。
- 配置生产环境变量、域名、HTTPS、CORS 白名单、数据库备份与日志轮转。
- 管理员初始账号/角色通过一次性数据库迁移或受控脚本创建，不允许用户自行注册管理员。
- 正式对外前启用邮箱验证或可靠密码重置；测试环境关闭确认邮件的设置不能带到生产。
- 先邀请 20–50 人内测，确认你能每日处理举报/高风险队列，再开放注册。

## 何时停止并找审查

迁移失败、JWT 无法验证、匿名内容显示公开资料、接口可传 userId 越权、密码/密钥进入日志或 Git、管理员接口无权限保护、准备上线但没有备份/举报处理能力。这些情况不要自行“快速修补”。
