# 05｜学习与面试清单

这份项目是你的实战作品。AI 可以写代码，但面试时你至少要能解释关键取舍、读懂主流程、独立定位一个小问题。每完成任务卡，按以下清单学习相关代码。

## 任务 0：工程与前端基础

你要理解：Maven 依赖、Spring Boot 启动类与配置文件；Vue 单文件组件、`ref/reactive`、组件 props/emits、Vue Router、Pinia 的用途；前后端分别如何启动。

面试可讲：为什么前后端分离；为什么使用单体而不是微服务；为什么用户端不用 Element Plus 作为主体。

## 任务 1：页面和状态

你要理解：响应式布局、组件拆分、列表渲染、筛选状态如何放在 URL/Pinia、为什么“待回答”排序在后端最终决定。

面试可讲：用户端如何兼顾匿名安全与公开答主主页；为什么不做楼中楼和排行榜。

## 任务 2：Java、数据库与认证

你要理解：

- Controller、Service、Mapper、Entity、DTO/VO 的责任边界；
- HTTP 状态码、全局异常处理、Bean Validation；
- MySQL 主键、外键、联合唯一键、索引、事务；
- BCrypt 为什么不能解密、注册/登录流程；
- JWT 的结构、认证过滤器、SecurityContext、为什么不能信任前端 userId；
- Flyway 为什么比手工改数据库更可靠。

面试可讲：注册登录如何做密码安全；JWT 鉴权如何拦截接口；数据库迁移如何随代码版本演进。

## 任务 3：最重要的业务与匿名边界

你要理解：

- 如何从 JWT 取得当前用户；
- Service 如何校验“是否为帖子作者”；
- Entity 为什么不能直接返回给前端；
- `PublicPostVO` 和“我的内容 VO”为什么不同；
- 如何让学校/专业参与 SQL 筛选却不出现在 API JSON；
- `@Transactional` 在发帖+标签关联、支持、标记有帮助中解决什么问题；
- MyBatis-Plus 用于基础 CRUD，自定义 SQL 用于复杂筛选的原因。

面试可讲：

> 我把匿名做成后端数据出口规则，而不是前端隐藏。数据库保留 author_id 处理删除、楼主权限和风控；公开接口仅构造白名单 VO，匿名时作者对象不含任何稳定身份字段。公开主页额外要求内容的 identity_mode 为公开，因此不能通过主页反查匿名历史。

## 任务 4：删除、通知与隐私

你要理解：软删除与硬删除的区别；为什么查询必须统一加 `deleted_at IS NULL`；通知如何由回复事件产生；浏览历史为什么只按当前用户查询；为什么 `robots.txt` 不能替代访问权限。

面试可讲：删除后如何避免分享链接泄露内容；如何设计用户可控的浏览历史。

## 任务 5：审核与风控

你要理解：举报和处罚为什么分开；限流的时间窗口；管理员 RBAC；审计日志；状态机；高风险求助为什么不自动处罚。

面试可讲：

> 我采用渐进式限制而非按举报次数封号。举报先进入审核，核实后才写入违规记录；账号按提醒、观察、限制、封禁升级，限制会真正作用于 Service 层的发帖/回复额度，并留下管理员审计记录。

## 任务 6：部署与工程化

你要理解：Docker 镜像、环境变量、CORS、HTTPS、数据库备份、日志脱敏、健康检查、生产与本地配置隔离。

面试可讲：项目如何从本地部署到服务器；如何防止密钥进入 Git；出现线上错误先看哪些日志和指标。

## 你应该亲自完成的练习

- 不看 AI 解释，画出“登录 → JWT → 访问发帖接口 → Service 校验 → 数据库写入”的流程图。
- 自己修改一个小功能：例如新增一个固定标签、改变帖子排序、增加一个输入长度校验；再运行测试。
- 使用 A/B 两账号故意请求越权接口，确认后端拒绝。
- 自己解释 posts、replies、users、reports 四张表为什么这样关联、哪些字段有索引。
- 准备 3 分钟项目介绍：产品问题、架构、匿名实现、最大难点、你的个人贡献、下一步优化。

## 面试底线

不要说“AI 写的”。可以诚实说“我使用 AI 辅助完成重复代码和测试，但架构、数据库边界、权限规则和验收由我设计与验证”。前提是你确实能解释每个核心模块、运行项目、修改一个小需求并定位常见错误。
